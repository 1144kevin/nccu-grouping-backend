# 一句話與可選語音訪談整合

## 使用流程

偷揪首頁統一為「一句話幫你揪」。可打字或使用語音說出餐飲需求、手上的優惠券、願意下單或取餐的意願。

- 直接找人：輸入後按「幫我揪」。未啟用者需本人按「啟用分身並幫我揪」，沿用原本 quick-start、規則配對與背景留意。
- 選填訪談：按「想講清楚，繼續聊聊（選填）」。分身整理摘要、最多三個補問、實際採用的地點／時間／預算來源。可以打字補充或用語音回答；語音回答結束後自動整理，不會自動儲存。
- 不必答完：只要餐點類型及必要資源意願已清楚，可以直接確認目前資訊開始找人。不需要經過完整表單，也不以舊訪談的 ready_for_review 為儲存門檻。
- 尚未釐清分類、資源承諾或無效時間時，先補必要資訊。未處理的新補充會暫停接受舊摘要，避免遺漏更正。

第一句語音結束只填回文字，讓本人確認後送出，不會僅因開啟麥克風就啟用分身。每次語音最多 60 秒；訪談每輪最多 1000 字、八輪及總共 4000 字。超過原一句話 160 字的輸入先進整理預覽，再以最多 160 字的摘要作為訊號標題，原始內容不直接截斷送出。

## 後端契約

新增 `POST /api/v1/stealth-cloud/quick-interview`，沿用 IntakeRequest 的 `turns` 與可選 `previous`。需本人登入，回應 no-store。

回傳 `facts`、`signal`、`sources`、`questions` 與 `interpretation`。signal 是待本人確認的 CloudSignalInput；必要資訊不清楚時為 null。此端點只讀本人近期需求，不啟用分身、不寫需求、不配對、不提交同意。

多輪理解沿用既有本機模型訪談、原句證據與更正保護。模型不可用時不丟掉補充而改存舊條件；未啟用模型時，第一輪可回傳清楚標示的關鍵字預覽，後續訪談回報不可用。舊的一句話入口仍可使用關鍵字模式。

擴充 quick-start 的可選 `confirmed_signal`。確認聊天摘要後，使用者提交這份已看過的結構化訊號；後端不再二次推論，也不重新計算相對時間。啟用分身仍需明確的 activate_agent，所有現有 RPC 權限與建立需求規則保留。

同 key 重試先找回已存訊號；確認型輸入比對完整訊號，不只比較標題。同 key 搭配不同預算、時間或角色會拒絕。前端保留失敗操作的 key 與完整快照，重試不重新產生時間。

## 配對條件

未提供時間時先找現在起兩小時，地點與預算可參考本人近 30 天最近的同類需求。歷史價格、取餐／下單責任與食品安全保證不沿用。

明確支持的飲料品牌優先於模型誤分類，品牌更正或取消限制後移除舊品牌標籤；不因模型說披薩就把 50 嵐優惠券配進披薩。只承認本人明確提出的資源與志願，朋友願意取餐不能當成本人的承諾。

## 驗收與環境

沿用上一輪 `NCCUPostSpeech` 與 Web SpeechRecognition。iPhone 需要包含語音模組的原生 App，Expo Go 與目前 Android 原生版本未支援此模組；瀏覽器不支援或權限被拒時，打字與訪談文字保留。Windows 不能替代 Mac Swift 編譯或 iPhone 實際收音驗收。

沒有新增資料表或修改雲端 migration。訪談暫存於畫面，換帳號或畫面卸載後不保留。離開前景／頁面時取消語音並忽略晚到回應；失敗可重試，待確認草稿不會自動變成公開拼單。

測試包括一句話直送、跳過選填補問、時間／預算更正、完整確認快照重試、角色與品牌約束、訪談只讀、登入與裝置邊界，以及語音輸入／回答／取消和換帳號。真實本機 Qwen 另以合成文字驗證飲料需求、地點預算補充、優惠券及順路取餐；不使用真人帳號，不向 Supabase 寫入資料。
