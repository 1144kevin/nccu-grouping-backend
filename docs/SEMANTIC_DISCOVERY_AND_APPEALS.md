# AI 訪談、申訴與語義候選發現：2026-10-20

範圍：本機 FastAPI／Expo + Supabase 開發專案 `axdwbfhrkbovgrbngrrh`。沒有部署、付費模型、推送遠端或 Apple 原生模型。

## 在 App 使用

後端重啟：Windows 在後端目錄執行 `.venv\Scripts\python.exe scripts\run_supabase_core.py`；Mac 為 `.venv/bin/python scripts/run_supabase_core.py`。App 依既有 `npm run dev:supabase` 啟動。沿用原有登入與本機模型設定，不需要建立新金鑰。

1. 偷揪訪談可補問、保留資訊。明確更正預算會採用最新原句；舊報價、時間與角色原句不能覆蓋更新。模糊／絕對時間仍要求相對時間，不自行猜測。
2. 兩個專用測試帳號各建立分身與本人確認的相容需求。在「偷揪結果」各按一次 **AI 搜尋新配對機會**。首次會建立自己的需求向量，對方未建立時可能沒有結果；30秒冷卻後再按即可。
3. 搜尋新增提案後，用原本 **AI 語義排序與判讀** 查看已授權摘要的理由及待確認事項。費用／分工仍由原流程編輯；先有意願，再全員確認同一版，才建立拼單與聊天室。
4. 「幫助與回報 → 申訴與覆核」可就本人已結案回報，或自己的內容處置，提出一次申訴。斷線重送原內容沿用 request key；不重複新增。
5. 指定管理者可在管理回報查看被檢舉原文，開始查核後回覆／結案、取消被檢舉拼單，或二次確認隱藏被檢舉訊息。訊息原文只保留給授權查核，聊天／預覽用提示取代，訊息搜尋也排除原文。
6. 管理者在「申訴與覆核」查看申訴並記錄覆核結果。版本衝突保留文字，須核對最新版本；不自動恢復已取消拼單、名額或舊同意。
7. 「內測資料與使用說明」採用假團隊／不可收信的 `.invalid` 信箱並明示草案性質。[政策草案與參考來源](PRIVACY_AND_TERMS_DRAFT.md) 列出目前行為與待實作的保留目標。

## 語義搜尋資料流與權限

```mermaid
flowchart LR
  A[本人已儲存需求] --> B[本機 Qwen 向量模型]
  B --> C[Supabase 私有 512 維向量]
  C --> D[同模型 cosine 候選搜尋]
  D --> E[既有硬條件與邀請額度驗證]
  E --> F[新的待確認提案]
  F --> G[原有摘要排序與模型判讀]
  G --> H[全員確認同版方案]
  H --> I[建立拼單與聊天室]
```

`core_signal_vectors` 不開放 anon／authenticated 直接讀寫。本人 session RPC 只能索引自己的有效需求；產生向量後資料庫重新檢查版本。其他人的原文、向量、擁有者識別碼與個別需求 ID 不透過搜尋結果回傳。

向量模型 ID 包含模型 digest、512 維與提示詞版本；不同模型不混算。更換模型後，其他帳號也須重新建立向量；不自動以管理憑證批次讀取所有人的原文。撤回／修改版本／內容會同步失效向量，刪除需求會連帶刪除向量；過期向量即使尚未清除，也不能用於搜尋。

第一版使用按模型分組的精確 cosine 搜尋，**未建立 HNSW／IVFFlat 近似索引**。每個本人需求最多取100個通過既有候選檢查的鄰居，每次新增最多3個雙人提案；既有規則配對及三人流程保留。相似度門檻0.2是未校準的開發設定，不是成功率、精準率或可接受價格的證據。

沿用既有 `stealth_candidate` 的地點、時間、預算、分類、飲食、封鎖、靜音時段、示範選擇與隔離測試範圍檢查，以及每日邀請額度、30秒冷卻、fingerprint 去重與 feature lock。高相似度不能擴張本人未接受的餐點類型或讓不相容候選成團。

新 API `POST /api/v1/stealth-cloud/matches/discover` 是明確操作，不在輪詢中自動呼叫。沿用免費本機模型設定與 session；裝置模式也納入受保護 AI 路徑。離線／模型錯誤不轉付費服務。搜尋前索引已提交，若搜尋遇冷卻，索引仍保留，稍後可重試。

## 資料庫變更

本開發專案已依序套用：

- `core_moderation_content`：被檢舉內容查核、訊息隱藏及原有私密稽核。
- `core_appeals`：本人與受處置作者的私人申訴、管理者版本化覆核、重試稽核。
- `core_semantic_discovery`：pgvector 擴充、私有向量表、失效 trigger 與候選建立 RPC。
- `core_semantic_discovery_validation`：RPC 向量與版本輸入檢查。
- `core_moderation_search`：訊息搜尋排除已隱藏原文，保留既有安全 wrapper。

沒有授予額外管理者，沒有處置現有真人內容。API 接受 App 既有的 opaque 重試字串，後端固定映射為資料庫 UUID，保留既有 UUID 客戶端；沒有把重試識別碼當作登入憑證。

新申訴／稽核列隨原案件刪除，申訴人隨 Auth 帳號刪除；不能把它誤寫成刪帳後仍保留固定年限。
