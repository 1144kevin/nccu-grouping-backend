## 隔離資料與操作分工

使用三個帶獨立 scope 的臨時 Auth 帳號：申請者、主揪、第三人。帳號準備沿用
`scripts/smoke_stealth_cloud.py` 的具 scope 保護與清理腳本；沒有透過註冊寄信、
取得真人帳號密碼或降低資料庫權限。

測試準備透過一般使用者 session 呼叫本機 API，建立三筆貼文與申請者偏好：

| 貼文 | 準備條件 | 預期 |
| --- | --- | --- |
| A | 相同標籤與地點偏好、剩一席、25 分鐘內截止 | 48 分，排 B 前面 |
| B | 相同偏好、剩兩席、一天後截止 | 36 分，排 A 後面 |
| C | 相同偏好、兩席均已占用 | 不進推薦 |

只有 C 的滿團狀態在準備階段透過 API 建立。A 的申請、主揪接受、雙方傳訊、
退出，全部由瀏覽器操作 App 按鈕完成。

## 已通過的畫面流程

1. 申請者登入 → 首頁「依我的偏好」：A 在 B 前，C 不出現。
2. A 顯示四種理由：標籤符合、地點符合、剩一席、30 分鐘內截止。
3. 點 A「想被揪」後顯示「取消申請」與「待主揪接受，尚未占用名額」，仍為 1/2 人。
4. 「拼單 → 申請／已加入」可追蹤 A；詳情沒有聊天室入口。
5. 登出申請者、登入主揪 →「拼單 → 我主揪的」→ A →「接受」。
6. A 變成「已額滿」、2/2 人、申請者「已加入」，可開啟拼單聊天室。
7. 主揪在聊天室送出測試訊息；申請者重新登入後從「訊息」看到未讀提示與同一聊天室。
8. 申請者讀到主揪訊息並回覆；主揪重新登入也讀到回覆。訊息確實存入開發資料庫。
9. A 滿團後不出現在推薦中，B 成為最前面的隔離測試貼文。
10. 申請者從詳情「退出並釋出名額」：A 回到 1/2 人，聊天室入口移除。
11. 退出者直接打開原聊天室網址，畫面拒絕讀取訊息；A 重新出現在推薦。
12. 第三個未加入 A 的隔離帳號直接開啟同一網址，也只能看到權限提示。

## 重跑準備

只對上述 Supabase 開發專案執行，先啟動既有本機 API 與 App。

```powershell
.venv\Scripts\python.exe scripts\prepare_recommendations_ui.py prepare
```

審閱忽略目錄的 `prepare.sql` 與 `cleanup.sql`，透過專案限定的 MCP 執行準備
SQL，再執行：

```powershell
.venv\Scripts\python.exe scripts\prepare_recommendations_ui.py setup
```

`accounts.json` 只供本機輸入測試登入使用，不提交、貼進聊天或截圖。依上方
清單操作 App；不要對保留的示範團或真人團送出申請。結束後先登出測試帳號，
再執行本 scope 的 `cleanup.sql`；確認剩餘帳號為 0 才移除 `accounts.json`、
`prepare.sql` 與 `posts.json`。保留安全報告與截圖即可。準備工具拒絕重複建立
同一批貼文，避免不小心累積資料。
