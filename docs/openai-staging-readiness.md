# OpenAI 測試部署準備（尚未部署）

## 隔離邊界

測試環境須使用獨立 Supabase 專案與測試帳號，不得套用共用專案的 URL 或資料。現有 `SupabaseCoreStore` 將 URL 固定為共用專案；`run_supabase_core.py --ai-provider openai` 故意拒絕啟動。雲端啟動檢查也尚未開放 OpenAI。兩處均須在實作隔離專案設定、驗證禁止共用專案後，才能部署測試服務。勿解除保護直接上線。

使用者後續已允許在現有專案新增明確標示的測試資料，但禁止更改正式資料與設定。這不等同資料庫隔離：測試貼文、通知和配對可能對正式用戶可見，現有向量 upsert 也會覆蓋資料。因此在確認帳號隔離、通知不外送、清理範圍及語意搜尋不得索引正式資料之前，不能直接執行既有 live smoke 腳本。原有腳本會讀寫帳號密碼且對其他帳號建立封鎖關係，不符合本次限制，不得使用。

PostgreSQL 測試容器禁用網路並僅使用合成資料。它不包含 Supabase Auth、Storage、PostgREST 或 pgvector，無法替代登入、照片、通知、完整拼單及端對端 AI 測試。

## 向量遷移與回退

現有 `core_signal_vectors` 以 signal_id 作主鍵，索引新模型會覆寫舊模型，即使查詢有 model_id 條件也無法安全回退。測試方案 `supabase/semantic_multi_model_staging.sql` 改為 `(signal_id, model_id)` 主鍵，透過檢查實際函式原文後修改 upsert；無法匹配預期內容時整個交易回滾。先確認部署版本，完整備份並在隔離專案使用 pgvector、現有 RLS 與正式版本的 SQL 做完整測試，不得直接套用。

1. 以合成資料驗證新舊模型的增、刪、更新、版本失效、權限、搜尋及封鎖條件；確認跨模型不能比對。
2. 將新舊模型同時保留，獨立產生新模型索引，統計活躍且未過期的需求與正確版本的新模型覆蓋率，並抽測排序與配對品質。現有程式僅索引當前使用者可存取的活躍需求；尚未實作全量重建程式，不應宣稱可全量切換。
3. 以開關針對測試環境切換讀取模型，監測缺索引、延遲、費用及配對品質；不應混用兩個空間的相似度。
4. 回退時先切回舊模型。需求若在新模型期間被修改，原索引失效觸發器會刪除所有模型向量，故必須重新建立缺失或過期的舊模型索引；保留舊列不等於零成本即時回退。回退前驗證覆蓋率與權限。
5. 事後經確認才考慮清理舊向量，並先備份。首頁語意排序目前即時計算向量，和上述需求向量表分開驗證。

## 預算保護

`supabase/openai_budget_staging.sql` 使用 PostgreSQL 交易 advisory lock 串行化所有後端工作程序的預留，硬編碼累計 50 美元與每日 10 美元（UTC 日界），單位為百萬分之一美元。`PostgresBudget` 已接入文字、圖片、向量與語音 OpenAI 路徑；尚未與實際的測試雲端資料庫與 Render 實機連線整合。開啟需私密金鑰、專用資料庫連線及 `CLOUD_OPENAI_SCHEMA_READY=true`，此旗標只表示操作者聲明、不能證明遷移已完成，部署前必須先實際驗證。

資料庫管理者應建立最小權限的專用登入角色，只授予 `ai_budget_private` schema USAGE 和 `reserve(text,bigint)` EXECUTE，禁止直接讀寫表及執行其他函式；以 TLS 連線。角色及連線資料由操作者自行設定，不放前端、版本控制或日誌。這些權限與連線需在隔離專案實測。

此帳本記錄保守預留而非帳單；失敗也保留，重啟不應重置。所有服務必須使用同一帳本，資料庫故障則拒絕新 AI 請求。本機既有 SQLite 預留額度要在切換時以安全、可稽核方式帶入，否則累計上限會重新開始。API 單價變動、單次實際消費高於預留、其他金鑰或應用繞過帳本、平台延遲、跨帳本，均可能使帳單高於設定；平台側用量限制和人工監控仍必須保留，不能保證絕對不超額。

## 上雲前阻礙

- 隔離 Supabase Auth、Storage、完整 schema 與測試資料未建立；沒有端對端驗證。
- OpenAI 雲端 provider、共享預算適配器已接線，仍需驗證全部 App 真實路由、專用角色權限及服務間連線，確保失敗不退回 Gemini/Ollama 或本機 SQLite。
- 多模型資料庫遷移和重建、回退尚未在真實 PostgreSQL + pgvector + Supabase 權限下測試。
- 部署主機、網址、Google OAuth 回跳、iPhone 推播、圖片大小和串流語音需在測試環境實測。
- 測試後確認隱私說明與 AI 語音揭露；勿記錄機密、使用者圖片或聊天內容。

## Render 和監控

目前前端 build 使用 `/api/v1` 相對路徑並仰賴本機 Node proxy；單獨部署 Render Static Site 前，必須準備正確的測試 API HTTPS 網址或安全的路由，並檢查 OAuth/PWA 及 SPA fallback。後端現有 ingress 假設可信單一代理來源 IP 與單一 `X-Forwarded-For`，Render 的實際 header 和來源必須依官方文件與隔離部署核對，不能使用寬鬆代理信任繞過安全檢查。

可以考慮把 UptimeRobot 免費方案監控設為測試後端 `/health`、每 5 分鐘一次；健康檢查不呼叫 AI 或資料庫。這只能減少因 15 分鐘無請求造成的休眠，不保證可用或阻止重啟、配額停機。單一服務連續運轉每 31 天約 744 小時；同一工作區所有免費 Web services 共享每月 750 小時，額外測試服務可能讓額度耗盡。Render 本機檔案是短暫的，SQLite 帳本不能用在雲端。
