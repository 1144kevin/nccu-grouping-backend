沒有部署、付費服務、OpenAI 呼叫或 push。這次是實際 API／資料庫／本機模型驗證，

## 訪談改動

- `/stealth-cloud/intake` 新增可選 `previous` 草稿；舊版只傳 `turns` 仍相容。
- App 補充時帶上上一輪成功結果。後端把它視為不可信輸入，再依之前的原句核對
  數字、時間、地點、角色與引用來源；不把它當作同意或驗證過的餐點。
- 本輪沒有提到的欄位群可沿用已有來源的值；有提及／更正／否定的欄位群採用本輪
  結果，缺資訊時補問，不直接復活舊值。過時草稿也不能蓋回已更正的預算。
- 明確後來願意取餐，可取代之前的拒絕；但短引句不能截掉「不願意」的否定字。
- 補問中／失敗後仍顯示上一輪摘要、地點、分工、金額與時間，不清空整張摘要。
  最新補充失敗會標示舊結果、保留輸入，停用套用直到成功重試，避免套用過時資料。
- 重開對話／切換帳號／元件卸載後不保存草稿。沒有新增伺服器對話儲存、資料表或
  自動同意；仍須本人核對表單再儲存，成團仍需全員同意同一版。

真實免費 `qwen3.5:4b` 測試：第一輪「政大正門，我想找人一起吃披薩，預算120元。」；
第二輪只補「從現在60分鐘後開始，持續120分鐘，我願意分食。」並帶前輪草稿。
結果兩輪完成、缺項為 0；120 元預算與正門仍保留，不再補問預算或地點。
這是單一合成情境的回歸結果，不代表所有中文對話都能兩輪完成。

## 隔離三人實測

| 情境 | 操作／實際結果 |
| --- | --- |
| 同時修改 | 兩個帳號同時寫 revision 0：一個 200、一個 409，沒有互相蓋掉 |
| 未全員同意 | 三人配對只有一人同意，formed_post_id 仍為 null |
| 成團前撤回 | 第三人撤回意願後，另一人確認回 409，無法強行成團 |
| 新需求 | 舊需求撤回，尊重真實 30 秒冷卻，使用新需求產生下一組配對，不復活舊邀請 |
| 自然過期 | 提出短期限方案，實際等待過期後確認回 409；沒有修改服務時鐘或直接改資料庫期限 |
| 改版 | 重新提出有效期限的第二版，同意數歸零，舊同意不沿用 |
| 三人成團 | 前兩人確認仍不成團；第三人確認後只有一筆 3/3 人正式拼單，三人都能讀聊天室 |
| 回應遺失重試 | 伺服器已提交，測試客戶端丟棄回應並模擬 ReadError；原請求重送回相同 post ID |
| 訊息重試 | 同一 Idempotency-Key 重送訊息，兩次回相同訊息 ID，聊天室僅一則 |
| 成團後退出 | 一位非主揪退出後變 2/3，該成員讀聊天室回 403 |

「斷線」使用受控的客戶端回應遺失模擬，不是真正關閉 Wi-Fi 或修改系統防火牆。
App 訪談另外驗證模型不可用、保留輸入與舊摘要、禁止套用過時結果；真機離線仍需 Mac／iPhone 驗收。
既有拼單及全員確認交易未放寬，本次沒有修改雲端 schema 或 RLS。
